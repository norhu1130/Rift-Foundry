# 실명 B0–B6 멀티플레이 연습 도구 실행표

## 준비

1. 두 계정으로 멀티플레이 연습 도구에 입장한다.
2. 1P는 Teemo, 2P는 Jax를 선택한다. 두 챔피언 모두 강인함이나 둔화
   저항 룬을 사용하지 않는다.
3. 게임 FPS를 60 이상으로 고정하고 같은 FPS로 화면을 녹화한다. Jax의
   상태 아이콘과 패시브 스택, 공격 결과가 보여야 한다.
4. Teemo를 9레벨로 올리고 Q를 5랭크로 만든다. Jax는 13레벨로 올린다.
5. 반복 사이에는 체력, 스킬 재사용 대기시간, 아이템과 패시브 스택을
   초기화한다. 측정 구간 도중에는 초기화 기능을 쓰지 않는다.

## 프레임 기록 규칙

- B0·B1·B5 시작: 실명 아이콘이 처음 보이는 프레임.
- B0·B1·B5 종료: 실명 아이콘이 처음 사라진 프레임.
- 첫 정상 공격 적중 프레임을 종료점으로 사용하지 않는다.
- 각 케이스를 5회 반복하고 원시 `start_frame`, `end_frame`, `fps`를 모두
  보존한다.

## 실행 순서

### B0 — 기준 지속시간

1. Jax의 아이템을 모두 비우고 강인함이 0인지 확인한다.
2. Jax가 Teemo를 계속 기본 공격하도록 명령한다.
3. Teemo가 Q를 적중시킨다.
4. 실명 아이콘 시작·종료 프레임을 기록한다.
5. 총 5회 반복한다.

### B1 — 강인함

1. Jax에게 Mercury's Treads(`3111`)만 장착한다.
2. 표시 강인함을 화면에 남긴다.
3. B0와 같은 위치와 행동으로 Q를 적중시킨다.
4. 아이콘 시작·종료 프레임을 기록하고 5회 반복한다.

### B2 — Cleanse

1. Jax에게 강인함 아이템을 제거하고 Cleanse를 장착한다.
2. Q가 적중해 실명 아이콘이 나타난 뒤 Cleanse를 사용한다.
3. 아이콘이 즉시 사라지고 다음 기본 공격이 정상 적중하면 `true`, 그렇지
   않으면 `false`로 기록한다.
4. 5회 모두 독립적으로 기록한다.

### B3 — Quicksilver Sash

1. Cleanse를 빼고 Jax에게 Quicksilver Sash(`3140`)만 장착한다.
2. Q가 적중해 실명 아이콘이 나타난 뒤 아이템을 사용한다.
3. 아이콘이 사라지고 다음 기본 공격이 정상 적중하는지 boolean으로
   기록한다.
4. 5회 반복한다.

### B4 — CC 면역

1. 별도 세션에서 Jax 대신 Olaf를 선택해 6레벨, R 1랭크로 설정한다.
2. Olaf가 R을 먼저 사용한 뒤 Teemo가 Q를 적중시킨다.
3. Q 피해가 들어간 장면을 보존한다. 동시에 실명 아이콘 유무와 기본 공격
   적중 여부를 확인한다.
4. Q는 맞았지만 실명이 적용되지 않으면 `true`, 실명이 적용되면 `false`다.
5. 5회 반복한다.

### B5 — 둔화 저항 음성 대조군

1. Jax에게 Boots of Swiftness(`3009`)만 장착한다.
2. 강인함은 0이고 둔화 저항만 있는지 확인한다.
3. B0와 동일하게 Q를 적중시키고 아이콘 시작·종료 프레임을 기록한다.
4. 5회 반복한다.

### B6 — 빗나간 공격과 Jax 패시브

1. Jax의 모든 아이템을 제거하고 패시브 스택이 0인 것을 확인한다.
2. Teemo Q가 적중한 동안 Jax가 Teemo에게 기본 공격을 정확히 한 번
   시도한다.
3. 공격이 빗나간 직후 Jax 패시브 스택이 1이 되면 `true`, 0이면 `false`다.
4. 매회 패시브를 0으로 초기화하고 5회 반복한다.

## 완료 후

측정 영상 경로와 관측 시각, 리뷰 정보를 fixture에 추가하고 상태를
`COMPLETED`로 변경한다. 그 다음 아래 명령을 실행한다.

```console
.venv/bin/python -m lol_build.scenarios.measurement \
  fixtures/measurements/cc_blind_16.17.1.pending.json --root .
```

검사 결과가 `READY_FOR_EVIDENCE_CHAIN`이어도 후속 패치 변경 검색이 끝날
때까지 메커니즘을 바로 `VERIFIED`로 승격하지 않는다.
